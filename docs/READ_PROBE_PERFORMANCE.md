# 读锁与文件头优化

2026-11-16：已实现全局锁拆分和自适应读块。随后按用户要求，**不使用 Computer Use，通过真实 Win32/WinFsp 调用完成原生对比**：并发读取三个文件头时，目录枚举及其返回属性从 1209 ms 降到 3.6 ms；包含强制属性刷新的整个流程从 1222 ms 降到 389 ms。目录枚举层的阻塞已显著改善，仍有同文件属性刷新和冷网络请求的等待。结果不代表 GUI 首帧或缩略图完成时间。

## 方案与实现

- 远端读取在短暂状态锁内校验句柄、复制节点并登记进行中的读取；取下载地址和 Range 下载在锁外进行。返回时重新检查暂存状态，若其他操作已截断、写入或删除并暂存文件，则读取当前暂存内容。
- 关闭句柄时，进行中的读取会保留对应 Entry 和暂存流，直到最后一个句柄及读取都结束再清理。暂存流读写仍在状态锁内串行执行，避免共享 seek 指针竞争。
- 孤立小读取按最多 64 KiB 窗口取数据；连续读取累计达到两个探测窗口后切回配置的大块，默认阈值 128 KiB、大块 4 MiB。大读取仍直接使用大块；小探测可以复用已缓存的大块。
- 读缓存增加独立短锁，同一版本、同一窗口的并发请求共享结果。网络期间不持有缓存锁；失效代次防止旧请求完成后把陈旧数据写回。缓存字节上限维持为 16 个配置大块，条目上限为 256。
- 目录元数据请求、写入暂存和上传仍沿用原同步规则；本次移出全局锁的是远端文件读取。

## 不使用 Computer Use 的原生调用验收

新增 `test/perf/native_cloud_probe.py`。每个样本重新挂载独立只读 X: 网络盘，用真实云盘相同的 12 项根目录；原有 Y: 保留。两组分别为读取一个已有 EXE 文件头，以及并发读取三个已有 EXE 文件头。每个文件由原生文件句柄无缓冲读取前 32 字节，FUSE 日志确认实际请求分别为 32/96 字节。每组前后各重挂 5 次，共 20 次挂载，使用默认 TTL 5 秒。

测试在取下载地址开始时通过子进程管道发出边界信号，主进程确认远端读已开始，再发起目录查询；没有注入网络延迟。记录的时间边界确认每个样本都发生真实读取重叠，且并发目录查询没有新增元数据 HTTP 请求。前后逐项验证名称、类型和大小摘要，以及每个文件头摘要相同；不输出或保存原始文件名和内容。

分开测量：

1. `os.scandir` 加 `DirEntry.stat`：取得枚举返回的名称、类型和大小。
2. 对每个返回路径额外执行 `os.stat`：强制查询更新的属性，并单独记录正在读取文件和其他文件的耗时。

这两个阶段不能混为一谈：Windows 的普通目录项可从枚举信息提供属性，独立 `os.stat` 则用于取得更新信息。[Python 的 DirEntry 文档](https://docs.python.org/3.14/library/os.html#os.DirEntry.stat)

核心状态锁以相同 RLock 语义的测试代理统计等待，快速属性查询不逐条写 DEBUG 日志；原实现和优化实现使用相同代理和诊断条件。信号、计时和记录仅在测试进程中添加，网络、文件系统实现和读块算法来自所选源码目录，未为测试修改真实服务数据。

### 剩余等待与结论边界

优化前的枚举先等待读操作，后续强制刷新已经很快；优化后枚举先返回，后续刷新才可能遇到尚未结束的文件读取。因此强制刷新阶段单独看会变长，应该比较完整流程。

优化后，单文件组的强制刷新阶段中位数约 163 ms，三文件组约 385 ms；其中正在读取文件的单次刷新中位峰值分别约 148/222 ms，其他文件约 1.1/0.8 ms。同时核心全局锁等待已很小。这将残余问题定位到核心锁之外、与同一正在读取文件的属性访问相关的路径，不能继续归因于 Python 全局锁。

WinFsp 官方并发模型说明了驱动仍会按单个文件协调访问。这与本次现象相符；本轮没有执行驱动 ETW 跟踪，不能把某个驱动锁作为已直接证明的唯一原因。[WinFsp 并发模型](https://github.com/winfsp/winfsp/blob/master/doc/WinFsp-API-winfsp.h.md#fsp_file_system_operation_guard_strategy---user-mode-file-system-locking-strategy)

验收结论：**真实挂载的目录枚举不再被文件头下载长时间拖住，多文件探测时完整属性查询流程也有明显改善。** 冷缓存网络等待和同文件强制属性刷新仍存在，不能保证所有资源管理器操作完全无停顿。本次按要求完成的是底层系统调用验证，不直接测量窗口绘制、第三方 Shell 扩展或缩略图呈现。
